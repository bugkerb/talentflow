## UAT-05 — ค้นหาผู้สมัคร

- URL: `http://127.0.0.1:3000/discovery`
- ขั้นตอนทำซ้ำ:
  1. เข้าสู่ระบบด้วยบัญชี Cloud E2E HR ที่สร้างแยกสำหรับรอบทดสอบ
  2. เปิด `/discovery`
  3. เลือกตำแหน่งงานจาก combobox `เลือกตำแหน่งงาน`
  4. กด `เริ่มค้นหา`
  5. ตรวจสอบกล่องยืนยันที่แสดงชื่อตำแหน่งงานที่เลือก
  6. กด `ยืนยันการค้นหา`
- Expected: ต้องเลือกตำแหน่งงานก่อนเริ่มค้นหา และหลังยืนยันต้องมี feedback ว่ากำลังค้นหาสำหรับตำแหน่งใด พร้อมแสดงผลผู้สมัครที่อ่านได้
- Actual: PASS — combobox เลือกตำแหน่งงานได้, dialog แสดงชื่อตำแหน่งที่เลือกตรงกัน, ยืนยันแล้วมี status `ค้นหาสำหรับตำแหน่ง` และผลผู้สมัครแสดงเป็น card
- Severity: ไม่มี
- Evidence: `tests/e2e/discovery.spec.ts` ตรวจ `option:checked`, dialog content, status และ candidate card โดย browser assertion ผ่าน

## UAT-06 — ตัดสินใจผู้สมัคร

- URL: `http://127.0.0.1:3000/discovery`
- ขั้นตอนทำซ้ำ:
  1. ดำเนินการ UAT-05 จนเห็น candidate card `กิตติพงษ์ วิริยะ`
  2. โฟกัสปุ่ม `อนุมัติเพื่อสัมภาษณ์` แล้วกด Enter
  3. ตรวจ `aria-pressed` และ status ของ candidate card
  4. โฟกัสปุ่ม `รอการตรวจสอบ` แล้วกด Space
  5. ตรวจ `aria-pressed` และ status อีกครั้ง
  6. โฟกัสปุ่ม `ปฏิเสธ` แล้วกด Enter
  7. ตรวจ `aria-pressed` และ status สุดท้าย
- Expected: ปุ่มอนุมัติ/รอตรวจสอบ/ปฏิเสธต้องกดได้จริงด้วย keyboard และทุก action ต้องมี feedback กับ state ที่เปลี่ยนชัดเจน
- Actual: PASS — ทั้งสาม action เปลี่ยน `aria-pressed` เป็น `true` และแสดง status ตาม action:
  - `อนุมัติผู้สมัครเพื่อเข้าสู่ขั้นตอนสัมภาษณ์แล้ว`
  - `เก็บผู้สมัครไว้รอการตรวจสอบเพิ่มเติมแล้ว`
  - `ปฏิเสธผู้สมัครแล้ว`
- Severity: ไม่มี
- Evidence: Playwright keyboard interaction และ DOM assertions ผ่านครบใน `tests/e2e/discovery.spec.ts`
