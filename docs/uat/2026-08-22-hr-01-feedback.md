## รายละเอียดตามข้อ

### UAT-01 — เข้าสู่ระบบ: PASS

- URL: `http://localhost:3000/login` → `http://localhost:3000/`
- ขั้นตอน: กรอกบัญชีทดสอบ HR แล้วกด “เข้าสู่ระบบ”
- Expected: เข้า Dashboard และเมนู Dashboard active
- Actual: URL เป็น `/`; พบ heading “วันนี้ต้องจัดการอะไรบ้าง”; ลิงก์ “แดชบอร์ด” มี `aria-current="page"`
- Evidence: DOM snapshot หลัง login แสดง `heading "วันนี้ต้องจัดการอะไรบ้าง"` และ `aria-current="page"`

### UAT-02 — Dashboard orientation: PASS

- URL: `http://localhost:3000/`
- ขั้นตอน: กดรายการ “ตรวจเรซูเม่ที่รอการตัดสินใจ” ใน “รายการที่ต้องทำ”
- Expected: ไปหน้าปลายทางที่สอดคล้อง
- Actual: ไป `http://localhost:3000/screening`; พบ heading “คัดกรองเรซูเม่”
- Evidence: URL หลัง click และ heading ของหน้าปลายทางตรงกัน

### UAT-03 — จัดการตำแหน่งงาน: PASS

- URL: `http://localhost:3000/jobs`
- ขั้นตอน: กรอก “Tech Lead” ใน searchbox, กด “เปิดรับ”, กด “ทั้งหมด (1)”, แล้วกด “แก้ไข”
- Expected: ค้นหา/กรองได้ และ action ตอบสนอง
- Actual: searchbox รับค่า `Tech Lead`, การ์ดตำแหน่งยังแสดง, ปุ่ม “เปิดรับ” มี `aria-pressed="true"`, ปุ่ม “แก้ไข” เปิดส่วนแก้ไขตำแหน่งงาน
- Evidence: DOM snapshot มี `searchbox "ค้นหาตำแหน่งงาน"`, `button "เปิดรับ" [pressed]`, และข้อความ “แก้ไขตำแหน่งงาน” หลัง click

### UAT-04 — สร้างตำแหน่งงาน: FAIL

- URL: `http://localhost:3000/jobs`
- ขั้นตอน: ไม่กรอก “ชื่อตำแหน่ง”, แผนก หรือรายละเอียด แล้วกด “บันทึกข้อมูล”
- Expected: บันทึกสำเร็จ หรือแสดง validation ที่บอกวิธีแก้ชัดเจน
- Actual: URL ยังเป็น `/jobs`, focus อยู่ที่ textbox “ชื่อตำแหน่ง” แต่ไม่พบข้อความ validation, `aria-invalid` หรือ alert อธิบายวิธีแก้
- Severity: High — ผู้ใช้ไม่รู้ว่าต้องแก้ข้อมูลใด และ workflow สร้างตำแหน่งงานไม่ให้ feedback ที่ชัดเจน
- Evidence: หลัง click DOM ยังมีฟอร์มเดิมและไม่พบข้อความ “กรุณาระบุ”, “ต้องกรอก”, “จำเป็น” หรือ validation alert

### UAT-09 — Responsive: PASS

- URL: `http://localhost:3000/`
- ขั้นตอน: ตั้ง viewport 390×844, ตรวจ Dashboard, กด “เปิดเมนูนำทาง”
- Expected: เมนูและ content ใช้งานได้ ไม่ชน/ล้นจอ
- Actual: `innerWidth=390`, `bodyWidth=390`, `scrollWidth=390`; ปุ่มเปลี่ยนเป็น “ปิดเมนูนำทาง”; dialog เมนูแสดงลิงก์หลักครบ
- Evidence: browser evaluate คืนค่า `scrollWidth: 390`; DOM พบ `dialog "เมนูนำทาง"` และลิงก์ Dashboard/Jobs/Discovery/Screening/Applications/Interviews

### UAT-10 — ภาษาและความเข้าใจ: FAIL

- URL: `http://localhost:3000/jobs`
- ขั้นตอน: เปิดหน้าจัดการตำแหน่งงานและอ่านข้อความบนหน้าจอ
- Expected: ไม่มีข้อความอังกฤษที่ไม่จำเป็น และ action สื่อผลลัพธ์ชัดเจน
- Actual: พบข้อความ `JOB DESCRIPTION` บนฟอร์ม ทั้งที่หน้าจอใช้ภาษาไทยเป็นหลัก; ปุ่ม action หลัก “บันทึกข้อมูล”, “แก้ไข”, “หยุดชั่วคราว”, “ปิดรับ” สื่อความหมายได้ชัดเจน
- Severity: Medium — ไม่ block การใช้งาน แต่ลดความสม่ำเสมอของภาษาและความเข้าใจสำหรับ HR ภาษาไทย
- Evidence: visible text scan ของ `/jobs` พบ `JOB` และ `DESCRIPTION`

## หมายเหตุ console

พบ error ระหว่าง development runtime: `eval() is not supported in this environment... React will never use eval() in production mode` จาก Next/React development bundle ไม่ใช่ข้อความจาก business UI และยังไม่ได้ใช้เป็นเหตุให้ fail UAT หลัก แต่ควรยืนยันซ้ำบน production build ก่อน release

## ข้อเสนอให้ทีม Dev

1. เพิ่ม inline validation หรือ alert ที่ระบุ field ที่จำเป็นใน UAT-04 และตรวจซ้ำด้วย browser
2. แปล `JOB DESCRIPTION` เป็น “รายละเอียดงาน” หรือเอาข้อความอังกฤษที่ซ้ำออก แล้วตรวจ UAT-10 ซ้ำ
3. รัน UAT-04 และ UAT-10 ซ้ำหลังแก้ โดยแนบ URL, DOM/screenshot และผล PASS/FAIL ใหม่
